## 整體架構

這一頁有兩種搜尋方式：

| 搜尋方式 | 用法 | 查詢方式 |
|---|---|---|
| **簡易搜尋** | 輸入一個值，按「搜尋」或 Enter | 同時查 12 個欄位，結果標示是哪個欄位符合 |
| **進階搜尋** | 新增多個條件，每個條件選一個欄位、填一個值 | 所有條件都要符合（AND）才會出現 |

兩種搜尋都是把請求送到伺服器的 `/api/db`，由伺服器去查資料庫，瀏覽器不持有任何 key。

## 一、共用工具

| 函式 | 行號 | 用途 |
|---|---|---|
| `escapeHtml(str)` | 1 | 把 `& < > " '` 轉成 HTML 安全字元。搜尋結果裡的資料（IMEI、檔名等）塞進畫面前都要先經過它，防止 XSS 攻擊 |
| `dbCall(op, params)` | 6 | **呼叫伺服器 `/api/db`**，所有資料庫查詢都透過它。成功回傳資料，失敗丟出錯誤（訊息是伺服器回的說明） |
| `csvCell(v)` | 19 | 匯出 CSV 時處理每一格，避免 Excel 把資料當公式執行。**這一頁目前沒有匯出功能，所以沒有用到它**，留著不影響運作 |

## 三、搜尋欄位設定

| 常數 | 行號 | 用途 |
|---|---|---|
| `SEARCH_FIELDS` | 44 | 可以搜尋的 12 個欄位，每一項是 `[資料庫欄位名稱, 畫面顯示名稱]`：IMEI1、Serial No.、MAC ID、Battery SN、PCBA SN、LCD SN、ICCID、PCB Main Board SN、SIM Unlock Code、Item Model、PO No.、Reference ID。簡易搜尋會逐一查這 12 個欄位；進階搜尋的欄位下拉選單也是用這份清單 |
| `RESULT_LIMIT_PER_FIELD` | 50 | 每個欄位最多顯示 50 筆。**目前這個數字實際上由伺服器 `api/db.js` 控制**，這裡改了不會生效；要調整請改 `api/db.js` 裡 `searchField` 的 `limit=50` |

> ⚠ `SEARCH_FIELDS` 要跟伺服器 `api/db.js` 裡的 `SEARCH_FIELDS` 一致。只改這裡、沒改伺服器的話，新增的欄位會被伺服器拒絕（「不允許的搜尋欄位」）。

## 四、簡易搜尋

| 函式 | 行號 | 用途 |
|---|---|---|
| `searchRecordsByField(query, dbField)` | 52 | 在**一個欄位**裡做模糊搜尋（包含就算符合），透過 `dbCall('searchField')` |
| `renderResults(query, recordResults)` | 56 | 把 12 個欄位的搜尋結果合併成一張表格，欄位有：命中欄位、值、機種、來源檔案、分頁、列。沒有結果時顯示「沒有裝置資料符合這個查詢」 |
| `runSearch()` | 91 | **簡易搜尋主流程**（見下方） |
| 搜尋按鈕的 `click` 事件 | 136 | 按「▶ 搜尋」時執行 `runSearch()` |
| 搜尋框的 `keydown` 事件 | 137 | 在搜尋框按 Enter 時執行 `runSearch()` |

**`runSearch()` 的流程：**
1. 讀取搜尋框的值，去掉前後空白。
2. **檢查輸入**（第 98～112 行），不符合就顯示錯誤、不送出：
   - 長度必須是 2～30 個字元
   - 只能有英文字母、數字、`(`、`)`、`&`
   - `&` 最多一個
3. 把按鈕改成「搜尋中…」並暫時不能按，畫面顯示「正在查詢資料庫…」。
4. **同時查 12 個欄位**（`Promise.all`），全部查完才繼續。
5. 用 `renderResults()` 畫出結果；失敗時顯示「查詢失敗：…」。
6. 不管成功或失敗，按鈕都恢復成「▶ 搜尋」。

> 表格裡的「列」是 `row_index + 2`：資料庫從 0 開始算，加 2 是因為 Excel 從第 1 列開始、而且第 1 列是表頭，這樣顯示的就是 Excel 裡的實際列號。

## 五、進階搜尋

| 函式 / 項目 | 行號 | 用途 |
|---|---|---|
| `conditionsList` | 142 | 放所有條件列的區塊 |
| `conditionRowCount` | 143 | 累計建立過幾個條件列，決定新條件前面要顯示「搜尋」還是「AND」 |
| `makeConditionRow()` | 145 | 產生一列條件：前面的「搜尋／AND」標籤、欄位下拉選單、輸入框、✕ 移除按鈕。按 ✕ 會刪掉這一列；在輸入框按 Enter 會執行進階搜尋 |
| `relabelConditionRows()` | 167 | 刪掉某個條件後重新整理標籤：第一列一定是「搜尋」，之後都是「AND」 |
| 「+ 新增條件」的 `click` 事件 | 173 | 新增一列條件 |
| 預設條件列 | 178 | 頁面打開時先放一列條件 |
| 「進階搜尋」展開按鈕的 `click` 事件 | 180 | 展開／收合進階搜尋區塊，箭頭在 ▸ 和 ▾ 之間切換 |
| `searchRecordsByConditions(conditions)` | 187 | 把所有條件送到伺服器，透過 `dbCall('searchConditions')`，最多回傳 200 筆 |
| `renderAdvancedResults(conditions, rows)` | 191 | 畫出進階搜尋結果。標題會列出條件，例如「IMEI1 包含「3567」　且　Item Model 包含「H500」」；表格欄位會依你選的條件動態產生 |
| `runAdvancedSearch()` | 224 | **進階搜尋主流程**（見下方） |
| 進階搜尋按鈕的 `click` 事件 | 272 | 按「▶ 進階搜尋」時執行 `runAdvancedSearch()` |

**`runAdvancedSearch()` 的流程：**
1. 收集所有條件列的「欄位＋值」，**沒填值的條件會自動略過**。
2. **檢查輸入**（第 233～252 行），不符合就顯示錯誤、不送出：
   - 至少要填一個條件
   - 每個條件最多 30 個字元
   - 只能有英文字母、數字、`(`、`)`、`&`
   - 每個條件的 `&` 最多一個
3. 按鈕改成「搜尋中…」，畫面顯示「正在查詢資料庫…」。
4. 送出查詢，用 `renderAdvancedResults()` 畫出結果；失敗時顯示錯誤。
5. 按鈕恢復成「▶ 進階搜尋」。

> 進階搜尋最少 1 個字元就能查（簡易搜尋要 2 個），這是沿用原本的設計。

## 簡易搜尋的流程

```
使用者輸入「3567」按 Enter
  → runSearch()
  → 檢查：2～30 字、只有英數和 ( ) &、& 最多一個
  → 同時呼叫 12 次 searchRecordsByField()
      → dbCall('searchField', { field: 'imei1', query: '3567' })
      → dbCall('searchField', { field: 'serial_no', query: '3567' })
      → ……（共 12 個欄位）
  → 伺服器 /api/db 再次檢查並查資料庫
  → renderResults()  畫出合併後的表格
```

## 要修改時看這裡

| 想改什麼 | 改哪裡 |
|---|---|
| 搜尋字數限制 | `runSearch()` 第 98 行、`runAdvancedSearch()` 第 238 行，**以及伺服器 `api/db.js` 的 `checkSearch`** |
| 允許的符號 | 第 103 行、第 243 行的 `/^[A-Za-z0-9()&]+$/`，**以及伺服器 `api/db.js` 的 `SEARCH_RE`** |
| 可以搜尋的欄位 | 第 44 行 `SEARCH_FIELDS`，**以及伺服器 `api/db.js` 的 `SEARCH_FIELDS`** |
| 每個欄位顯示幾筆 | 伺服器 `api/db.js` 的 `searchField` 裡 `limit=50` |
| 錯誤訊息文字 | 各個 `errorMsg.textContent = '…'` |

> 前端的檢查是讓使用者馬上看到錯誤；伺服器的檢查才是真正擋住繞過網頁直接送請求的人。所以規則要改的話，**兩邊都要改**，否則可能出現網頁允許、但伺服器拒絕的情況。
